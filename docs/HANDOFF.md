## 관리자 체험
1. 홈 맨 아래 ‘운영자’를 누르거나 [운영자 화면](http://127.0.0.1:5173/admin)을 엽니다.
2. ‘로컬 운영자 체험하기’를 누릅니다. 이 로그인은 개발용이며 실제 본인 계정 인증이 아닙니다.
3. ‘상품 관리’에서 왼쪽 상품을 고릅니다. 제목, 브랜드, 추천 이유, 이미지·쿠팡 주소, 카테고리와 모음집을 수정할 수 있습니다.

6. ‘초안 저장’을 누르고 ‘미리보기’에서 확인합니다.
7. ‘로컬 화면에 반영’을 누르면 이 컴퓨터의 홈 화면이 바뀝니다. 인터넷에 배포되는 버튼은 아닙니다.

저장한 초안은 새로고침해도 유지됩니다. 서로 다른 창에서 동시에 저장하면 이전 내용으로 덮어쓰지 않고 충돌을 알립니다. 저장 실패 시 편집 중인 내용은 화면에 남습니다. 새 상품을 실수로 추가했다면 저장 전 ‘새 상품 추가 취소’를 누릅니다.

## 공개 전에 필요한 사항
- 지금 주소는 쿠팡 파트너스 가입에 제출할 공개 홈페이지 주소가 아닙니다. 사용자가 최종 Vercel 배포와 공개 주소 생성을 직접 진행하기로 했습니다. 이번 작업에서는 외부 배포를 하지 않습니다.
- 사용자 결정에 따라 상품 사진 18개는 공란으로 둡니다. 상품 설명·출처·쿠팡 링크는 그대로 표시합니다. 사진을 표시하려면 승인된 파트너스 자료, 직접 촬영 사진 또는 사용 허락을 받은 이미지인지 확인해야 합니다.
- 사용권 확인 전 사진의 주소는 방문자 데이터에서 제외하며 이미지를 요청하지 않습니다. 상품 자체는 유지합니다. 관리자의 원본 이미지 주소는 보관하고, 사진 변경 시 사용권 상태는 다시 확인 전으로 돌아갑니다. ‘연결·공개 준비 → 공개 화면 미리보기’에서 공란 상태를 볼 수 있습니다.
- 공개 운영자는 Supabase 이메일·비밀번호로 로그인합니다. 본인 Auth 사용자 UUID를 Vercel 환경변수 `ADMIN_USER_ID`에 등록하고 저장소를 연결해야 합니다. 전체 설정은 [Vercel 안내](VERCEL.md)를 따르세요.
- 파트너스 가입 후 본인 제휴 링크를 각 상품에 등록하고 ‘연결·공개 준비 → 쿠팡 파트너스 제휴 안내 표시’를 켭니다. 안내 설정만 켜서는 수익이 발생하지 않습니다.
- 상품 자동 갱신과 쿠팡 주간·월간 인기 순위는 아직 연결하지 않았습니다. 실제 API 권한과 제공 데이터를 확인한 뒤 진행합니다. 현재 추천을 쿠팡 공식 인기 순위로 표시하지 않습니다.
- 일부 상품은 이미지와 판매 옵션의 패키지·수량이 다를 수 있습니다. 실시간 재고·가격·배송도 미확인입니다. 가격대 필터나 임의 가격·평점은 넣지 않았습니다.
- 방문자 회원가입·분석 도구·클릭 집계는 연결하지 않았습니다. 현재 방문자 화면은 외부 상품 사진을 요청하지 않습니다. 사용권 확인 후 사진 표시를 켜면 해당 이미지 서버와 통신합니다.
- 유료 서비스 신청, 도메인 구매, 배포는 하지 않았습니다. 월 3만 원은 예산 상한이며 실제 요금 확정이나 지출 승인이 아닙니다.

## 저장·Git 상태
로컬 데이터는 `.local/content.sqlite`에 저장됩니다. 이전 `.wrangler/state`의 초안·공개본을 이 파일로 복사했고 원본은 보존했습니다. 두 폴더 모두 Git과 배포 파일에서 제외합니다. Supabase용 SQL은 준비만 했으며 외부 데이터베이스에 적용하지 않았습니다.

첫 로컬 커밋은 main 브랜치의 f8acb93입니다. 규정 보완 작업 브랜치는 fix/partners-compliance입니다. 사용자 요청에 따라 [GitHub 저장소](https://github.com/hyun-pixel/-)에 이 브랜치를 저장합니다. 이 저장소는 공개 저장소이므로 소스 코드와 이 문서를 누구나 읽을 수 있습니다. 실제 커밋·원격 동기화 상태는 git log -1과 git status -sb로 확인할 수 있습니다. GitHub에 소스를 올리는 작업과 웹사이트 배포는 별개이며, PR·merge·웹사이트 배포는 진행하지 않았습니다. 비밀키를 코드에 넣지 않았으며 `.env*`, `.dev.vars*`, 로컬 저장소와 의존성 폴더는 Git 제외 대상으로 설정했습니다.

## Vercel 전환 (2026-10-02)

표준 Next.js 빌드로 전환했습니다. Cloudflare 런타임·빌드 도구·Sites 로그인 연결을 제거했습니다.
방문자 화면은 별도 환경변수 없이 기본 상품으로 실행합니다. 온라인 관리자 편집은 Supabase 연결 후 사용할 수 있습니다. [배포 설정과 관리자 연결 순서](VERCEL.md)를 확인하세요.

검증: Next.js 배포 빌드·TypeScript 통과, 자동 테스트 23개 통과, lint 오류 0개(기존 이미지 최적화 권장 경고 2개). 390·768·1440px 브라우저에서 검색·상세·더 보기·사진 공란을 확인했습니다. 별도 개발용 저장소에서 로그인·저장·미리보기·반영·새로고침·로그아웃과 충돌/외부 요청 차단을 확인했습니다.

테스트용 인증·저장 서버를 연결한 운영 빌드에서 본인 계정만 허용, HttpOnly·Secure 쿠키, 로그아웃·해지된 세션 차단, 저장 실패 503 처리를 확인했습니다. 로컬 PostgreSQL 호환 엔진에서 테이블 SQL과 RLS·역할별 권한을 확인했습니다. 실제 Supabase 프로젝트를 연결한 검증은 아직 하지 않았습니다. 기록은 preview/vercel-browser-qa.json과 preview/vercel-supabase-qa.json에 있습니다.

기본 브랜치는 `fix/partners-compliance`입니다. Vercel 전환 변경도 이 브랜치에 통합하며, 포함된 작업 브랜치는 정리합니다. Vercel 프로젝트 설정은 별도로 변경하지 않았습니다. 최신 커밋·원격 동기화 상태는 `git log -1`과 `git status -sb`로 확인하세요.

## 쿠팡 파트너스 검토·보완 (2026-10-02)

검토 근거는 [공식 이용 가이드, 2025년 10월](https://partners.coupangcdn.com/partners-guide/partners-guide-20251028182159.pdf)과 [2026년 9월 7일 시행 개정 공지](https://influencers.coupang.com/announcements/203)입니다. 개정 공지는 확인했지만 파트너스 사이트 접근 제한으로 최신 운영정책 전문은 확인하지 못했습니다. 신청 시 본인 계정의 ‘약관 및 정책’에서 현재 적용 문서를 확인해야 합니다. 사이트 수정만으로 최종 승인이나 수익 발생을 보장하지 않습니다.

### 이번에 바꾼 내용
- 가이드 25~26·63쪽: 실제 제휴 링크가 있으면 홈·목록 시작 부분에 공식 수수료 안내를 표시합니다. 제휴 상품의 발견 노트에서도 사진·본문보다 먼저 표시합니다. 안내 본문은 모바일·PC 모두 16px이고, 배경과 구분되는 색상을 사용합니다. 상품 카드에도 광고·제휴 링크를 구분합니다.
- 일반 링크만 있는 현재 화면에는 수익을 받고 있다는 문구를 표시하지 않습니다. 단축 제휴 링크뿐 아니라 lptag가 포함된 상품 주소도 구분하며, 제휴 안내를 체크하지 않은 공개 대상 제휴 상품의 저장을 막습니다. 주소 형식 검사이므로 계정 소유와 실제 수익 연결까지 검증하는 것은 아닙니다.
- 가이드 67쪽 취지에 맞춰 구매 버튼이 내용을 가리지 않도록 상세창 아래의 일반 영역에 배치합니다. 사진·제목·더보기는 사이트 안에서만 작동하고 쿠팡으로 자동 이동하지 않습니다.
- 쿠팡 버튼은 등록한 원래 주소로 바로 연결합니다. 새 창 보안 설정은 유지하고 방문 출처는 도메인까지만 전달합니다. 기존 /go 주소는 예전 링크 호환용으로 남깁니다. 직접 연결은 추적 경로를 단순하게 하는 구현 선택이며, 모든 중간 이동 방식이 규정 위반이라는 뜻은 아닙니다.
- 가이드 64~65쪽: 쿠팡 공식 서비스와 혼동하지 않도록 독립적인 큐레이션 사이트임을 알립니다.
- 가이드 68·71쪽: 사진 공란, 출처·날짜, 에디터 추천과 인기 근거의 구분을 유지합니다. 사진 주소가 없어도 확인 전 상태로 상품을 저장할 수 있으며, 사용권 확인 완료 상태에는 실제 사진 주소가 필요합니다.
- 관리자 ‘연결·공개 준비’에 제휴 링크 수, 공개 주소 등록, 활동 화면 제출 순서와 공식 문서 링크를 추가했습니다.

### 사용자가 준비할 순서
1. [Vercel 안내](VERCEL.md)에 따라 수정된 소스로 직접 배포하고 공개 주소를 만듭니다. 배포 후 관리자 편집을 사용하려면 Supabase 연결도 완료하세요.
2. 쿠팡 파트너스의 ‘내 정보’에서 실제 활동 페이지 주소를 등록합니다. 공개 주소가 없는 지금의 127.0.0.1 주소는 제출할 수 없습니다.
3. 본인 파트너스 계정에서 발급한 상품 링크를 관리자 ‘상품 관리 → 쿠팡 상품·파트너스 링크’에 등록합니다. ‘연결·공개 준비 → 쿠팡 파트너스 제휴 안내 표시’를 체크합니다.
4. ‘초안 저장 → 미리보기 → 사이트에 반영’ 순으로 확인합니다. 현재 로컬 버전의 마지막 버튼은 ‘로컬 화면에 반영’이며 인터넷 배포와 다릅니다.
5. 실제 공개 화면에서 제휴 링크와 수수료 안내가 보이게 캡처한 뒤 파트너스가 요구하는 활동 스크린샷으로 등록합니다(가이드 23~24쪽). 검수용 가상 링크 캡처를 제출하면 안 됩니다. 실제 계정의 최신 제출 안내를 따르세요.

### 이번 검증 결과
- 테스트 20개, TypeScript 검사, 배포용 빌드 통과.
- 320·390·768·1440px 브라우저 검사: 가로 넘침 없음, 광고 안내 16px, 닫기 버튼과 안내 겹침 없음, 고정 광고 버튼 없음.
- 실제 데이터: 상품 18개·사진 공란 유지, 방문자 이미지 요청 0건, 일반 링크 유지.
- 복제한 별도 로컬 저장소에서만 제휴 상품 2개와 일반 상품 16개를 섞어 검사했습니다. 실제 클릭 전에 외부 이동이 없고, 구매 버튼을 눌렀을 때만 정확한 등록 주소가 새 창으로 열림을 확인했습니다. 쿠팡 외부 통신은 테스트에서 가로채 실제 클릭을 보내지 않았습니다.
- 관리자에서 안내 없는 제휴 상품 저장 차단, 운영 빌드의 비로그인 변경 차단 확인. 원래 초안·공개 데이터는 변경하지 않았습니다.
